# Trickcal : Shooting Balddagu

에르핀 공격·회복·날개 수정까지 포함한 최신 단일 실행 파일은 `release/TSB-Multiplayer-ErpinMotions.exe`입니다. 개발 버전은 `Play-ErpinMotions.cmd`로 실행합니다. 좌클릭은 이동 중 마력탄, 우클릭은 누르는 동안 케이크 회복이며 놓거나 다른 행동을 하면 취소됩니다. 남은 조각은 떨어진 뒤 3초 후 사라집니다. [구현·조작·검증](docs/ERPIN_MOTIONS.md).

Fyrox 1.0.1로 만든 **3D FPS / 경쟁전식 2CP / 6 대 6 멀티플레이 MVP**.
민트색 BLOOM과 분홍색 COCOA가 선택한 전장의 A → B 거점을 공격·수비합니다. **요정왕국 성** (`fairy-kingdom-castle`)과 **엘프 도시** (`elf-city`)를 맵 선택 화면에서 고를 수 있습니다.

## 실행

### 단일 EXE 테스트판

최신 배포본은 `release/TSB-Multiplayer-ErpinMotions.exe`입니다(2026-11-17 패키징). 현재 소스와 에셋으로 다시 빌드했으며, 15명 원작 Move·이동 중 팔 공격과 에르핀 마력탄·케이크 회복·독립 날개 모션을 포함합니다. [이동 동작](docs/MOVE_MOTIONS.md), [에르핀 동작](docs/ERPIN_MOTIONS.md)을 참고하세요. 아래 파일들은 이전 배포본입니다.

3인칭 무기 크기 수정판은 `release/TSB-Multiplayer-WorldWeaponSize.exe`입니다. 아야·에르핀·피코라·우이·버터·힐데·시온의 무기를 원작 비율에 맞춰 확대했습니다. [캐릭터별 조정과 검증](docs/WORLD_WEAPON_SIZE.md)을 참고하세요.

클로에가 양팔을 쭉 펴서 세바스티안의 양 볼을 받치는 최신 자세 수정판은 `release/TSB-Multiplayer-ChloeStraightArms.exe`입니다. 현재 작업 모델에도 반영했습니다. [자세 수정과 검증](docs/CHLOE_CARRY_POSE.md)을 참고하세요.

세바스티안·에루 크기 수정판은 `release/TSB-Multiplayer-CompanionSize.exe`입니다. 원작 이미지 비율에 맞춰 두 동료를 확대하고 우이 탑승 높이와 선택창 구도를 조정했습니다. [변경 내용과 검증](docs/COMPANION_SIZE.md)을 참고하세요.

15명 공통 팔 리깅 수정판은 `release/TSB-Multiplayer-ArmRigFix.exe`입니다. 긴 머리·망토·몸통 의상에 남아 있던 팔 가중치를 제거하고, 실제 손·소매 움직임은 유지했습니다. [수정 범위와 검증](docs/ARM_WEIGHT_ISOLATION.md)을 참고하세요.

볼·눈 감기·리뉴아 외투 수정판은 `release/TSB-Multiplayer-FacialRig.exe`입니다. 볼 피부만 넓고 둥글게 당겨지며, 눈썹과 윗속눈썹이 함께 내려오는 3단계 깜박임과 리뉴아의 원래 외투를 적용했습니다. [변경 내용과 검증](docs/CHEEK_INTERACTIONS.md)을 참고하세요.

이드의 탑승 자세까지 조정한 수정판은 `release/TSB-Multiplayer-IdSeated.exe`입니다. 커진 초승달 좌석에 골반을 붙이고, 무릎을 접어 발을 내부 받침에 올렸습니다. [탑승 자세 변경과 검증](docs/ID_SEATED_POSE.md), [탑승물 크기 변경](docs/ID_MOUNT_SIZE.md)을 참고하세요.

최신 손·소매 메시 정리판은 `release/TSB-Multiplayer-PolishedHands.exe`입니다. [손·소매 메시 정리](docs/HAND_MESH_POLISH.md), [손 리깅 수정](docs/HAND_RIG_FIX.md), [생성 모델·얼굴·모션 적용](docs/MESHY_ASSETS.md)을 참고하세요.

`release/TSB-Multiplayer-ErpinMotions.exe` 하나만 다른 PC에 복사해 더블클릭하면 됩니다. 게임, 런타임 DLL,
에셋 및 테스트용 EOS 설정을 포함하며, 최초 실행 시
`%LOCALAPPDATA%\TSB\SingleFile\빌드해시`에 자동으로 풀어 실행합니다.
로그는 해당 폴더의 `artifacts/logs`에 저장됩니다. 별도 설치나 관리자 권한은 필요 없습니다.

두 PC에서 같은 EXE를 실행한 뒤, 호스트는 **플레이 → 방 만들기 → 코드 복사하기**로
로비에 표시된 방 코드를 전달하고, 참가자는 **플레이 → 방 참여하기 → 방 코드 입력란에서 Ctrl+V → 참여하기**를 누릅니다.
호스트가 **게임 시작**을 누르면 방장과 참가자 모두 **캐릭터 선택 화면으로 자동 이동**합니다. 각자 캐릭터를 확정하면 경기에 입장합니다.
같은 PC에서 두 창을 테스트하려면 기존 `--host` / `--join` LAN 옵션을 사용하세요.

단일 파일에 포함된 진단은 `TSB-Multiplayer-ErpinMotions.exe --check-eos`,
`TSB-Multiplayer-ErpinMotions.exe --check-relay-host --seconds 300`,
`TSB-Multiplayer-ErpinMotions.exe --check-relay-join eos:호스트ID:소켓 --seconds 300`으로 실행합니다.
결과는 `artifacts/logs/launcher-프로세스번호.log`에 기록됩니다.
`--verify-only`는 패키지와 캐시 파일의 무결성을 검사합니다.

재빌드 절차는 [단일 EXE 패키징](docs/SINGLE_EXE.md)에 있습니다.

### 소스에서 실행

Rust stable과 Windows MSVC 빌드 도구가 필요합니다 (검증 환경: Rust 1.95.0). 그래픽은 OpenGL을 사용합니다. 기본 EOS 빌드는 [EOS SDK 설정](docs/eos-setup.md)이 필요합니다. 첫 빌드에는 시간이 걸립니다. 별도 에셋 다운로드나 Fyrox 에디터 설치는 필요 없습니다.

```powershell
# 제작사 크레딧 → 로그인 / 회원가입 / 게스트 선택 → 홈 → 플레이
cargo run --bin tsb

# 웹사이트 없이 EOS 방 생성 (로비의 ‘코드 복사하기’ 버튼으로 복사)
cargo run --bin tsb -- --eos-host
# 참가자: 받은 EOS 방 코드로 접속
cargo run --bin tsb -- --join "eos:호스트ID:방소켓"

# 혼자 연습 (네트워크 불필요)
cargo run --bin tsb -- --solo

# 두 번째 맵: 엘프 도시 (로비에서도 선택 가능)
cargo run --bin tsb -- --solo --map elf-city
```

제작사 로고와 로그인·회원가입·게스트 선택을 마치면 캐릭터 일러스트와 트릭컬 SHOOTING BALDDAGU 로고가 있는 **홈 화면**이 열립니다. **플레이 → 대전 로비**에서 **방 만들기 / 방 참여하기**를 선택하세요. 방 목록이나 8자리 방 코드로 참여합니다. 별도 EOS 방 코드와 LAN `IP:포트` 입력도 지원합니다. 기본 실행은 방 만들기를 누를 때 EOS 방을 열고, `--host`와 `--join`은 지정한 방에 미리 연결합니다. `--solo`는 방 만들기로 오프라인 연습 방을 엽니다. 소셜·프로필은 게임 안의 계정 화면을 엽니다. 친구 검색·요청·수락·거절·취소·삭제·차단·초대 참여와 이름·닉네임·사용자 ID·소개·색상 편집을 지원합니다. 최초 로그인/재연결은 기존 웹 인증을 사용하며, 사진 업로드는 웹 프로필에 남아 있습니다. 게임 종료는 프로그램을 닫습니다. [서버 적용 및 검증](docs/INGAME_ACCOUNT.md). 배경 제작 기록과 로고 출처는 [홈 화면 문서](docs/HOME_SCREEN.md)에 있습니다.

로비에는 **우리 팀 / 상대 팀 각 6칸의 닉네임·영웅 프로필**, **맵 선택 카드**, **영웅 선택·게임 시작 버튼**이 있습니다. 맵 카드를 눌러 **요정왕국 성 / 엘프 도시** 중 하나를 고르고 **이 맵 선택**으로 확정하세요. 방 생성 전 선택도 유지되며 참가자는 방장이 선택한 맵을 자동으로 받습니다. **인원을 채울 필요 없이 혼자서도 시작**할 수 있습니다. 빈 슬롯은 그대로 비어 있으며, 방장이 빈 유저 블록을 누르면 **15명 중 원하는 영웅을 골라 봇을 추가**할 수 있습니다. 봇 블록을 다시 누르면 **영웅 변경 / 봇 삭제**가 가능합니다. 같은 팀 영웅 중복 금지와 포지션별 최대 3명 규칙을 적용합니다. 상대 팀이 비어 있으면 경기 시간과 거점 진행을 멈춰 **시간 제한 없이 자유롭게 연습**할 수 있습니다. 프로필 사진은 선택한 영웅 초상화를 사용합니다. **영웅 선택**에서 확정하면 로비로 돌아옵니다. 방장이 **게임 시작**을 누르면 경기 준비가 시작되고, 연결된 모든 플레이어가 **캐릭터 선택 화면으로 자동 이동**합니다. 각자 영웅을 확정하면 경기에 입장하며, 기존 8초 준비 시간은 그대로 진행됩니다. Esc는 선택창 → 로비 → 홈 순서로 돌아가며, 방을 종료하려면 **방 나가기**를 누릅니다. [대전 로비 문서](docs/LOBBY.md).

선택창의 큰 캐릭터 **볼을 왼쪽 버튼으로 누른 채 드래그**하면 늘어나며 고유 반응을 보여줍니다. 놓으면 볼이 복원되고 캐릭터별 놓기 모션이 재생됩니다. 현재 15명 모두 지원하며 [원작 조사와 구현 범위](docs/CHEEK_INTERACTIONS.md)를 확인할 수 있습니다.

영웅 선택에서 **초상화 클릭·방향키는 미리보기**, **선택 확정 버튼·F5는 실제 선택**입니다. 선택 버튼과 팀 편성 칸은 얼굴 중심의 2D 일러스트를 사용하며, 뒤쪽 3D 캐릭터는 바스트샷으로 확대해 선택 모션을 보여줍니다. **F5**는 로비에서 시작, 로비에서 연 선택창에서는 선택 확정, 경기 중에는 복귀로 동작합니다. 참가자는 두 팀의 빈 슬롯부터 배정되며, 빈 슬롯이 없으면 봇을 대체합니다. 최대 12명까지 참가할 수 있고, 연결이 종료된 슬롯은 빈 자리로 돌아갑니다. 봇 편집은 방장/오프라인 연습에서 경기 시작 전·종료 후에 가능합니다. H와 Esc로 화면을 열어도 경기는 계속 진행됩니다. `--auto-start`와 기존 전투 검증 모드는 홈·로비를 건너뜁니다.

한 PC에서 두 창을 테스트하려면 첫 창을 `--host 0.0.0.0:28080`로 실행하고, 다른 터미널에서 `cargo run --bin tsb -- --join 127.0.0.1:28080`을 실행하세요. 엔진 로그는 실행별 `artifacts/logs/tsb-프로세스번호.log`로 분리합니다.

```powershell
# 그래픽 없는 전용 서버: 첫 참가자 접속 시 첫 경기 시작, 이후 로비에서 서버 콘솔 Enter로 시작
cargo run --no-default-features --bin tsb-server -- 0.0.0.0:28080

# 대체 포트
cargo run --bin tsb -- --host 0.0.0.0:28081

# 검증
pwsh -File scripts/verify.ps1

# 그래픽 검증까지 실행하고 메뉴/플레이 PNG 저장
pwsh -File scripts/verify.ps1 -Smoke

# 클라이언트와 전용 서버 실행 파일 생성
cargo build --bins
# 이후 프로젝트 루트에서 target/debug/tsb.exe 직접 실행 가능

# 15명 모델의 춤 앞/뒤 30개 GPU 캡처 후 종료
cargo run --bin tsb -- --art-review

# 15명 선택창과 원본 Spawn 모션 캡처
cargo run --bin tsb -- --selection-review

# 사도별 사망 모션·탑뷰·녹화 재생·부활 복귀 GPU 검증과 66장 캡처
cargo run --bin tsb -- --deathcam-review --auto-start

# 요정왕국 성 구조·스폰 HUD 10장 + 설정화 공간 9장, 총 19장 캡처
cargo run --bin tsb -- --map-review --auto-start

# 유령 벽 통과 5장 + 조각상 표면 파문 전·발생·소멸 3장 GPU 캡처
cargo run --bin tsb -- --ghost-review --auto-start

# 유령 영체화: 준비·잔여 시간·쿨타임·사용 불가·사망·선택 화면 10장 검증
cargo run --bin tsb -- --solo --auto-start --phase-review
# 위 명령에 --hud-review-small을 추가하면 960×640 배치를 확인합니다.

# 보호막 생성·피격·만료·정령·거대화·사망 7개 GPU 화면 검증
cargo run --bin tsb -- --shield-review --auto-start

# 15명 1인칭 그림자와 인사·점프·3인칭 전환 GPU 검증
cargo run --bin tsb -- --shadow-review --auto-start

# 설정 메뉴·블러·감도 저장·복귀 GPU 검증 (검증용 설정은 artifacts에 격리)
cargo run --bin tsb -- --solo --auto-start --settings-review
# 별도 실행에서 저장값 복원과 960×640 화면 확인 (위 검증 후 실행)
cargo run --bin tsb -- --solo --auto-start --settings-review --settings-review-reload --hud-review-small
```

기본 방 생성은 **EOS P2P**이며 호스트·참가자 공유기의 포트포워딩 없이 직접 연결 또는 Epic 중계를 사용합니다. 두 PC에 같은 EOS 제품 설정과 DLL이 필요합니다. `--force-relay`로 중계만 사용하는 점검을 할 수 있습니다. `--lan`, `--host IP:포트`, `--join IP:포트`는 기존 직접 UDP 경로이며 외부에서 호스트 포트에 도달할 수 있어야 합니다. 공유기·방화벽 설정을 자동 변경하지 않습니다.

DotG 프로필·친구·초대는 [온라인 실행 안내](docs/dotg-online.md)를, 외부 폴더의 EOS SDK 연결과 로그인 점검은 [EOS 설정 안내](docs/eos-setup.md)를 참고하세요. 게임플레이의 EOS 전송이 연결되어 있으며, 실제 두 PC 접속은 `tsb-eos-peer-check`로 직접/중계 연결을 별도 검증합니다. 로그인·NAT 조회 성공만으로 상대 PC 접속 성공을 뜻하지 않습니다.

## 조작

경기 중 캐릭터 머리 위에 **플레이어 이름과 잔여 체력 바**가 표시됩니다. 이름은 배경 없이 그림자와 함께 표시하고, 아군은 민트색·적군은 분홍색으로 구분합니다. 봇은 `BOT · 영웅 이름`을 사용합니다. 이동·앉기·거대화에 맞춰 위치를 따라가며, 사망·빈 슬롯·벽 뒤·화면 밖에서는 숨깁니다. 자신의 이름표는 춤의 3인칭 시점에서 표시됩니다. `cargo run --bin tsb -- --solo --auto-start --nameplates-review`로 12개 상태의 화면 검증을 실행할 수 있으며, `--hud-review-small`을 더하면 960×640으로 확인합니다.

| 키 | 기능 |
|---|---|

## 구현된 흐름

엘프 공용 텔레포트는 이드·리뉴아·힐데가 사용합니다. 45m 안의 충분히 넓은 벽·바닥·천장을 겨냥해 설치하며, 같은 색을 다시 설치하면 해당 입구가 교체됩니다. 두 색을 모두 설치하면 모든 플레이어가 통과할 수 있고 시선과 이동 속도가 출구 방향으로 변환됩니다. 사망·캐릭터 교체·라운드 초기화 시 설치한 포탈은 사라집니다. 막힌 출구와 맵 경계 밖 설치는 허용하지 않습니다. 오른쪽 하단의 공용 스킬 사각형은 노랑/파랑 반쪽으로 나뉘어 개별 쿨타임을 표시합니다. 포탈 시야는 관찰 위치에 따라 변하며, 중첩된 포탈의 재귀 렌더링은 생략합니다. 새 네트워크 프로토콜(TSBL)이므로 호스트와 접속자는 같은 빌드를 사용해야 합니다.

`tsb --solo --portal-review --lan`은 노랑·파랑 포탈의 실시간 시야, 비스듬한 시점과 분할 HUD를 캡처하는 검증 모드입니다.

- **툰 렌더링**: 원작 캐릭터 이미지의 밝은 색면과 갈색 윤곽선을 참고해 3단계 조명, 무광 재질 응답, 깊이 기반 윤곽선을 기본 적용했습니다. 15명 캐릭터·1인칭 팔과 무기·두 전장에 적용되며 원래 표정과 그림자는 유지됩니다. [조사·구현·화면 비교](docs/TOON_RENDERING.md). `--render-standard`로 기존 PBR 화면과 비교할 수 있습니다.

- **2CP 경기 HUD**: 팀별 점수·공수 역할·남은 시간과 A/B 거점 마름모만 간결하게 표시합니다. 점령률은 공격팀 색이 마름모 안을 아래부터 채우는 면적으로 표현하며, 별도 점령 문구·백분율 막대는 사용하지 않습니다. [구현·화면 검증](docs/OBJECTIVE_HUD.md).

- **라운드 승패 연출**: 라운드가 끝나면 0.9초 동안 0.16배속 슬로모션으로 마지막 움직임을 보여준 뒤, 원작을 참고해 생성한 초록색 VICTORY/보라색 DEFEAT 그래픽과 `라운드 승리`/`라운드 패배`를 표시합니다. 최종 승패·무승부도 지원하며 기존 공수 교대와 같은 로비 복귀 시간을 유지합니다. [원작 조사·생성 프롬프트·검증](docs/ROUND_RESULTS.md). 화면 검증은 `cargo run --bin tsb -- --solo --auto-start --round-results-review`입니다.

- **원작 기반 일반 평타 모션**: 15명의 원작 `Attack1_1`을 분석해 전신과 1인칭 손·무기에 적용했습니다. 비비의 쌍검과 버터의 새총 당기기를 포함하며 공격 속도 변화·점프·데스캠에도 동일한 동작 시계를 사용합니다. [조사·각색·검증](docs/BASIC_ATTACK_MOTIONS.md).

- **자기 캐릭터 그림자**: 1인칭에서도 실제 전신과 월드 무기가 그림자를 만듭니다. 자기 몸은 카메라 화면에서 숨기고, 그림자에는 현재 애니메이션을 그대로 사용합니다. 춤의 3인칭 시점과 데스캠 대상 전환 시 표시 상태를 복원하며 화면용 팔·무기는 중복 그림자를 만들지 않습니다.

- **Esc 설정 메뉴**: 화면을 블러 처리하고 설정·게임 복귀·게임 로비로 돌아가기·방 나가기 버튼을 표시합니다. 게임 로비로 돌아가면 현재 방 접속·맵·편성·채팅을 유지하며 경기는 계속됩니다. 로비의 경기 복귀 버튼으로 다시 플레이할 수 있습니다. 방 나가기는 현재 접속과 방장인 경우 방 등록을 정리하고 홈으로 돌아갑니다. 방에 들어가지 않은 홈에서는 방 관련 버튼을 숨깁니다. 설정에서 마우스 감도를 슬라이더·좌우 방향키·−/+ 버튼으로 0.10~5.00배까지 조절하며 기본값은 1.00배입니다. 변경 사항은 자동 저장되고 다음 실행에 적용됩니다. Windows 저장 위치는 `%LOCALAPPDATA%\TSB\settings.json`으로 실행 폴더와 단일 EXE의 빌드별 캐시가 바뀌어도 유지됩니다. 시온의 조준 줌에도 같은 감도 설정과 기존 확대 배율 보정을 적용합니다. Esc는 설정 → 메뉴 → 게임 순으로 복귀하며, 채팅·커뮤니케이션 휠·캐릭터 선택 중에는 기존 취소 동작을 유지합니다.

- **경기 종료 후 로비 복귀**: 승패·무승부 결과를 5초간 표시한 뒤 방장과 참가자 모두 같은 게임 로비로 돌아옵니다. 방 코드·접속·팀 슬롯·선택 캐릭터·봇·맵·채팅을 유지하며 경기 점수와 전투 상태만 초기화합니다. 방장은 로비에서 맵과 편성을 조정하고 다시 시작할 수 있습니다. 전용 서버는 복귀 후 대기하며 서버 콘솔에서 Enter를 누르면 다음 경기를 시작합니다.
- **팀 보이스 채팅**: 기본 마이크·스피커를 사용해 같은 팀 인간 플레이어끼리 실시간 음성 대화를 합니다. 호스트·참가자·전용 서버에서 동작하며, 첫 상태는 음소거입니다. 플레이에 들어간 뒤 **M**으로 마이크를 켜고 끄며, 왼쪽 위에 `캐릭터 초상화 · 스피커 · 플레이어 이름` 목록을 표시하며 내 항목은 항상 첫 줄에 고정합니다. 내 마이크가 음소거되면 스피커와 X 표시가 빨간색으로 바뀌고, 발화 중에는 청록색 음파와 밝은 이름으로 표시합니다. 같은 팀의 실제 참가자만 표시하며 봇과 빈 슬롯은 제외합니다. 음소거해도 팀원 음성은 들립니다. 선택창·사망 중에도 사용 가능하고, 텍스트 채팅에서 M을 입력하거나 키를 길게 누르면 토글하지 않습니다. 홈·연결 끊김·다른 창으로 이동 중에는 캡처와 송신을 중지합니다. 창으로 돌아오면 이전 마이크 상태를 따릅니다. `--solo`에서는 음성 장치를 열지 않습니다. 마이크 오류는 HUD로 안내하고 M으로 다시 시도합니다. 출력 장치 오류는 기본 스피커를 확인한 뒤 게임을 다시 실행하세요.
- `--solo --auto-start --voice-review`는 음성 장치를 열지 않고 음소거·활성·발화·발화 중 음소거·포커스 이탈·6명 팀·캐릭터 선택 화면을 캡처합니다. `--hud-review-small`을 더하면 960×640 배치를 검사합니다.
- 보이스는 기존 게임 UDP 포트를 사용합니다. 16 kHz 모노 PCM16을 20 ms 단위로 전송하며 발신자당 약 32 KB/s, 서버는 같은 팀의 나머지 인원에게 중계합니다. 짧은 재생 버퍼와 큐 상한·오래된 음성 폐기로 지연 누적을 막고, 인증 토큰·주소·순번·전송률을 검사합니다. 음성은 파일로 저장하지 않습니다. 현재 LAN 프로토타입에는 음성 암호화·에코 제거·잡음 억제가 없으므로 헤드셋 사용을 권장합니다.
- **데스캠**: 사망하면 탑뷰에서 해당 사도의 사망 모션(약 1.83–3초)을 끝까지 보여준 뒤, 처치 전 최대 3초부터 처치 순간까지 녹화된 상대 시점을 재생합니다. 다른 사도·공격·투사체도 당시 상태로 되돌아가며 실제 전투는 계속됩니다. 부활 즉시 내 시점으로 복귀하고 H 사도 변경·채팅·점수판을 유지합니다. [동작·출처·검증 상세](docs/DEATH_REPLAY.md).
- **8방향 커뮤니케이션 휠**: 12시부터 시계방향으로 감정 표현 → 안녕 → 치유 요청 → 집결 → 궁극기 상태 → 음성 대사 → 응답 → 감사. 감정 표현은 기존 춤, 안녕은 1인칭 손 흔들기와 다른 플레이어에게 보이는 상체 인사 모션으로 연결합니다. 실행 내역은 파란 팀 채팅에 표시하며 궁극기 충전율은 서버가 결정합니다. 음성 대사는 회색 ‘준비 중’ 칸과 안내만 있으며 소리·채팅 전송은 하지 않습니다. 0.75초 재사용 간격, 재전송 중복 방지, 포커스 이탈 취소를 적용했습니다. [조사·구현 설명](docs/COMMUNICATION_WHEEL.md).
- **팀 채팅은 파란 글씨**, **경기 채팅은 주황 글씨**. 팀 메시지는 서버에서 아군에게만 전달하며 경기 메시지는 전원에게 전달합니다. Enter로 열고 전송, Tab으로 채널을 바꿉니다. 영웅 선택·게임 로비·맵 선택에서도 같은 채팅을 사용하며, 화면·맵·방 전환 시 최근 내역과 작성 중인 내용은 유지하고 송수신 대상만 현재 방으로 바뀝니다. 이전 방의 기록은 새 방에 전송하지 않습니다. 로비·맵 메뉴는 클릭이나 Space, 영웅 확정은 버튼이나 F5를 사용합니다. 한글 IME·좌우/Home/End·Backspace/Delete 편집, 최대 160자·최근 64개 기록을 지원합니다. 입력 중 이동·공격·스킬·시점 조작을 막고, 모든 화면에서 오른쪽 하단에 표시하며, 새 메시지나 채팅 입력 없이 10초가 지나면 2초 동안 완전히 투명해집니다. Enter나 새 메시지로 다시 표시됩니다. UDP 전송·수신 확인 및 재전송으로 중복 표시를 방지합니다.
- 승인된 15명 선택, 팀 내 같은 캐릭터 중복 금지, 상대 팀 미러 허용, 포지션별 최대 3명.
- 같은 성격 두 명마다 **팀 전체 공격력 +20%**, 가산·최대 +60%. 사망해도 편성 시너지는 유지.
- **유령(벨라·시온) 공용 스킬 — 영체화**: Shift를 한 번 누르면 3초 동안 건물 벽과 엄폐물을 통과합니다. 패시브 벽 통과는 제거했습니다. 종료 시 벽 안에 있으면 가까운 빈 공간으로 튕겨 나오며, 이후 12초 쿨타임이 시작됩니다. 계속 누르고 있어도 재발동하지 않습니다. 조준점 주변 링과 소수점 초 표시로 잔여 시간을 확인하고, 마지막 1초는 금색으로 표시합니다. 오른쪽 하단 E 옆의 Shift 슬롯은 사용 중·쿨타임·준비·사용 불가 상태를 표시합니다. 접촉 위치의 실제 모델 표면에 나타나는 파문과 바닥·천장·맵 외곽·탄환 충돌은 유지합니다. 벽 안에서는 캐릭터 변경이 잠깁니다.
- 종족 특성: 요정 치유 +10%, 엘프 재장전 -10%, 정령 비피격 4초 후 9.6 보호막, 용족 밀쳐내기 저항, 마녀 일반 스킬 쿨타임 -5%. Shift 질주와 수인의 질주 +8%는 제거했으며, 유령의 벽 통과는 위 공용 스킬로 전환했습니다.

## 현재 범위

오버워치 경쟁전의 2CP 구조를 참고한 프로토타입이며 특정 시즌 규칙 전체의 동일 구현은 아닙니다. 짧은 준비 시간, 점령 속도와 고정 오버타임 유예는 MVP에 맞췄습니다. 점령 속도 가속은 거점에 있는 공격자 3명에서 상한에 도달합니다. 상세 규칙은 [MVP 사양](docs/MVP.md), 전체 캐릭터와 패시브 수치는 [로스터 설계](docs/ROSTER_PLAN.md)를 참조하세요.

EOS P2P 또는 직접 UDP로 방장 PC에 연결합니다. 참가자 이동은 60Hz로 예측하고 서버가 확인한 입력 이후만 재적용하며, 충돌과 점프는 서버와 같은 계산을 사용합니다. 피해·스킬·거점·부활은 계속 서버가 결정합니다. 서버 사격 판정의 과거 시점 보상과 상용 안티치트는 없으며, 높은 지연·손실 환경의 실제 두 PC 검증은 별도로 필요합니다. 호스트가 나가면 경기가 끝나며 재접속은 클라이언트를 다시 실행합니다.

캐릭터는 원작의 머리·의상·장식을 참고해 새로 제작한 MVP 3D 모델입니다. 표정과 의상 형태는 단순화했고 페이셜·손가락 리깅·의상 물리·캐릭터/전투 음향은 후속 범위입니다. 원작 이미지와 2D 모션 자료는 출처와 함께 조사 폴더에 보관하며, 게임은 새 FBX 모델을 사용합니다. 삼면도의 일부 측후면과 춤은 팬게임용 해석입니다. 원작 기본 버전의 스킬 정체성을 FPS용 사거리·수치·입력으로 각색했으며 원작 계수·확률·장비·성장 시스템의 동일 재현은 아닙니다. 홈·영웅 선택·HUD·채팅은 `assets/fonts/ONE Mobile POP.ttf`를 사용해 한글을 표시합니다. 실행 시 이 폰트 파일이 필요하며 Windows 시스템 글꼴 설치 여부에 의존하지 않습니다. 맵에 배치된 간판·안내판·차량 번호·스폰 문구는 `assets/fonts/Hungeul.otf`로 제작해 맵 메시 안에 포함합니다. 글꼴에 없는 방향 화살표(↑/→)는 도형으로 표시하며, 저장된 맵의 문구만 갱신할 때는 `scripts/update_map_fonts.py`를 Blender에서 실행합니다.

Blender 검사로 15명 리그, 165개 동작, 60개 반복 동작의 연결을 확인하며 실제 Fyrox 캡처도 보관합니다. 별도 PC와 인터넷 환경은 아직 검증하지 않았습니다. 연결 표시의 RTT는 입력 송신부터 해당 입력을 확인한 상태 수신까지의 왕복 시간(서버 갱신 대기 포함)이며, 그 아래 실제 렌더링 FPS를 표시합니다. 5초마다 PERF 로그에 FPS·렌더링/플러그인 갱신 시간·마지막 상태 수신 후 경과 시간을 남깁니다.

초안 단계에서는 과거 실행 파일·배포본·모델 백업·검증 로그·화면 캡처를 장기 보관하지 않습니다. `artifacts/`의 실행·검증 결과는 확인 후 삭제하며, 제작 스크립트가 입력으로 읽는 이미지·모션 원본·출처 기록만 유지합니다. 기존 작업 문서의 `artifacts/` 경로는 당시 기록이므로 정리 후에는 파일이 없을 수 있습니다. 로컬 실행에는 `target/debug/tsb.exe`를 사용합니다.
