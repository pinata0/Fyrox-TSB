## 루프 1 — 서버 권위 시뮬레이션

- 렌더링 의존성 없는 `game.rs` 작성. 3 대 3 팀, A/B 순서, 두 공수 라운드, 점령 틱/감소, 경합, 오버타임, 최고 점령률 비교를 구현.
- 양쪽 완전 점령 시 타임뱅크를 보정하고 추가 라운드 진행. 0초 대 60초 이상인 경우 단독 추가 공격과 1/3 승리 조건 구현.
- 이동, 점프, 엄폐물 충돌, 사격/탄창/재장전, 아군 피해 차단, 리스폰/보호 추가.
- 봇은 격자 BFS로 거점을 찾아가며 시야가 확보된 적에게 오차 있는 조준으로 발사.
- 검증: 첫 규칙 회귀 테스트 11개 통과. 이후 봇 1분 전투 시뮬레이션 검증 추가.

## 루프 2 — UDP 멀티플레이

- 호스트/참가 및 그래픽 없는 전용 서버. 빈 봇 슬롯을 참가자로 대체하고 연결 종료 시 봇이 인계.
- 버전 헤더/세션 토큰/입력 순서 번호, 입력 범위 검증, 300ms 입력 중단, 8초 연결 타임아웃, 수신 작업량 제한.
- 60Hz 서버 판정 + 20Hz 전체 상태 전송. 경기 재시작과 독립적인 스냅샷 순서 번호 유지.
- 최초 샌드박스 실행에서는 로컬 UDP 수신이 차단됨. 로컬 네트워크 권한으로 재실행해 코드 문제와 환경 문제를 분리.
- 발견: Windows의 과대 데이터그램이 WSAEMSGSIZE(10040)를 반환해 서버를 종료함. 해당 패킷만 무시하도록 수정.
- 검증: 프로토콜 단위 테스트 2개, 실제 두 UDP 클라이언트 통신 테스트 2개 통과. 이동 동기화/공수 팀 배정/재시작/잘못된 패킷 포함.

## 루프 3 — Fyrox 장면과 HUD

- 절차 생성 슈가 가든 맵, 엄폐물·중앙 통로·나무·거점 경계, 두 팀 볼따구 도형 캐릭터.
- FPS 카메라, 무기·총구 섬광·트레이서·명중/피격 표시, 체력·탄창·점령·시간·팀 기록 HUD.
- Enter 시작, 마우스 잠금, 포커스 상실 시 입력 해제, ESC 커서 복귀, F10 종료.
- 발견/수정: Fyrox 1.0.1 UI 메시지 API가 이전 예제와 달라 현재 `ui.send` API로 변경.
- `cargo check --offline` 통과 후 첫 실행에서 빈 UI 컨테이너 접근으로 패닉 발견. UserInterface를 명시적으로 생성해 수정.
- 실행 화면에서 HUD가 보이지 않는 문제 발견. 크기가 0으로 측정되는 중첩 Canvas를 제거하고 UI 루트에 배치.
- F10 종료 동작과 3D 장면 렌더링을 실제 창에서 확인. 다른 전체 화면 앱과 OS 캡처가 간섭해 이후 시각 QA는 게임 자체 GPU 프레임/HUD를 읽어 PNG 저장하는 방식으로 변경.
- 첫 PNG 검토에서 구체의 구멍/겹침 발견. Fyrox 1.0.1 구체 생성 구현에서 서로 다른 slices/stacks 값이 문제를 일으킴을 확인하고 16/16으로 맞춤. 무기 부품의 겹치는 평면도 조정.
- `--smoke-test`는 메뉴/플레이 렌더 저장, 자동 이동·사격·재장전, 12초 후 종료. 캡처나 참가 연결 검증이 실패하면 종료 코드 1 반환.
- 동시 호스트/참가 실행 시 첫 프레임보다 캡처가 앞서는 경합 발견. 첫 장면 렌더 완료를 기다리도록 수정 후 재검증.
