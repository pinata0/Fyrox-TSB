# 요정왕국 성 / Fairy Kingdom Castle

2026-11-13, 설정화 공간 개정 v3. Slug는 `fairy-kingdom-castle`을 유지한다. 공격팀이 A 왕실 정원을 확보한 뒤 B 왕관 광장을 점령하는 6 대 6 / 2CP 맵이다. v2에서 재구성한 아누비스의 꺾이는 진행축·비대칭 우회로·고저차 위에, 사용자가 제공한 설정화 9장의 공간과 사물을 구현했다.

원본 9장은 `assets/references/fairy-kingdom-castle/concept/`에 보관하며 `manifest.json`에 SHA256과 설정화 번호를 기록한다. 24가지 사물 유형을 56개 인스턴스로 배치했다. 지붕·창·기둥·벽체 등의 건축 모듈은 별도로 조립한다. `object-catalog.json`은 각 사물의 위치·회전·공간·참고 이미지 번호·메시 수를 기록한다. Blend의 `Object / ...` 컬렉션과 메시의 `asset_id`, `concept_images`, `space` 속성으로 대응 사물을 찾을 수 있다.

설정화의 형태를 해석해 실제 입체 메시로 모델링했으며, 그림을 배경판에 붙인 방식이 아니다. 보이지 않는 뒷면·깊이·실내 크기는 게임 동선에 맞춰 구성했다. 이미지에서 원작 메시나 정확한 치수를 복원한 것은 아니다. 창빛은 밝은 창 재질과 11개 실내 보조광으로 표현하며 원화의 손그림 질감·볼류메트릭 광선을 그대로 재현하지는 않는다.

## 배치

![충돌 데이터 기반 평면도](../artifacts/fairy-kingdom-castle/layout-plan.png)

- 외접 경계: X −22~68m, Z −54~38m. 실제 이동 영역은 L자이며, 남동쪽 정원 절벽은 유령도 통과할 수 없는 경계다. 접근로에서 B로 대각선 지름길을 만들 수 없다.
- 초기 공격 스폰 `(5, 0, -45)` → 넓은 접근 마당 → 외성문 `(2, 0, -8)`. 양쪽 건물의 크기와 내부 통로가 다르다. 서쪽 집을 통과하는 길이 별도 관문으로 연결된다.
- A `(0, 0, 12)`: 서쪽 2층 창문 회랑과 동쪽 높은 성채가 서로 다르다. 동쪽 성채는 나무 중정으로 들어갈 수 있으며 양쪽 문 위치를 어긋나게 두어 직접 사선을 막는다. 성채 앞 돌출 고지대와 외곽 발코니는 3.6m이며, 서쪽 회랑 계단과 동쪽의 짧고 조밀한 계단으로 올라간다.
- A → B: 성채와 연결부 건물이 직접 시야를 차단한다. 북쪽 길은 성채 뒤를 돌아 동쪽으로 꺾이고, 남쪽 길은 전면 고지대 옆으로 돌아 B 측면 통로에 연결된다. 두 거점을 일직선 관문으로 연결하지 않는다.
- B `(46, 0, 15)`: 공격 방향이 +X로 바뀐다. 중앙 관문, 넓은 북쪽 방과 굽은 칸막이, 좁은 남쪽 회랑과 두 번 꺾이는 출구를 각각 걸을 수 있다. 기둥 12개와 왕좌를 갖춘 지상 홀이다. 중앙 다리와 연결 계단·착지대·난간·받침기둥은 제거했으며, 다리 전용 상부 출입구는 벽으로 마감했다.
- 공격 전진 스폰 `(-13, 0, 26)`은 A 옆에 둔다. 수비 스폰 `(58, 0, 30)`은 B 뒤의 같은 방을 A/B 단계에 걸쳐 사용한다. 모든 스폰 슬롯과 점령 구역은 분리된다.
- 흰 벽체·민트색 지붕·금색 왕관·기둥·왕좌·정원 장식을 구조 위에 입혔다. 배경 왕성과 세계수도 B의 동쪽으로 이동했다.

원본의 구역 관계와 수직 동선을 재구성했으며 문 폭·계단 치수·거점 간 거리는 TSB 이동 규격에 맞췄다. 원본의 모든 벽과 치수를 1:1로 복제한 것은 아니다. 다인 실전 밸런스는 별도 플레이 검증이 필요하다.

## Blender와 게임 연결

- 편집 원본: `assets/maps/fairy-kingdom-castle/fairy-kingdom-castle.blend`. 구역별 컬렉션, 56개 사물 컬렉션, 구조 카메라 4개와 설정화 공간 카메라 9개.
- 게임 모델: 같은 폴더의 `fairy-kingdom-castle.fbx`. 지역·재질별로 묶어 내보내며 Fyrox가 직접 불러온다.
- 구성 사물: 서로 직각으로 향하는 왕관 관문, 비대칭 건물과 성채, 돌출 고지대, 창문 회랑, 북쪽 방·남쪽 통로, A 고지대 계단 2개, B 홀 기둥 12개, 왕좌와 단상 계단, 돔·첨탑·문장·조명·벤치·정원·세계수.
- `layout.json`의 동일한 충돌 블록을 Blender와 Rust가 사용한다. 가구·화단·난간·기둥의 단순 충돌 영역과 상세 시각 메시를 분리하고, 계단·방 입구의 통행을 검사한다. Blender 변환은 `(game.x, -game.z, game.y)`, FBX 가져오기 배율은 기존 캐릭터 파이프라인과 같은 `0.01`이다.
- `build-report.json`에 정점·삼각형·객체·내보내기 청크 수를 기록한다. 생성 과정에서 중복 정점·퇴화 면을 정리하고 법선·UV를 만든다.

```powershell
python scripts/castle_layout.py
& 'C:\Program Files\Blender Foundation\Blender 5.3\blender.exe' --background --python scripts/build_castle.py -- --render
powershell -ExecutionPolicy Bypass -File scripts/render_castle_plan.ps1
cargo build --locked --bins
target/debug/tsb.exe --map-review --auto-start
powershell -ExecutionPolicy Bypass -File scripts/review_castle_concepts.ps1
```

`castle_layout.py`가 기본 구조를, `castle_concept_layout.py`가 방문 공간·가구 충돌·조명을 정의한다. `castle_concept_assets.py`는 사물 모델링, `castle_scenery.py`는 공간 조립, `build_castle.py`는 Blender 검증·내보내기를 담당한다. `--render`는 13개 Blender 시점, `--concept-render`는 설정화 공간 9개만 렌더한다. 두 옵션을 빼면 Blend·FBX만 생성한다. `--map-review`는 기존 구조/HUD 10장과 공간 9장, 총 19장을 저장한다. 마지막 9장에서는 공간 관찰을 위해 캐릭터와 공중 거점 표식만 숨긴다. 일반 플레이에는 적용하지 않는다. 결과는 `artifacts/fairy-kingdom-castle/` 및 `artifacts/preview-map-*.png`에 있다.

## 로비 대표 이미지

`assets/maps/fairy-kingdom-castle/preview.png`는 왕좌실 정면의 실제 게임 스크린샷이다. `--map-review --auto-start`의 마지막 `throne` 시점(플레이어 위치 `(43, 0, 15)`, yaw `π/2`, pitch `0.16`)에서 HUD·무기·캐릭터·거점 표식 없이 촬영한 `artifacts/preview-map-throne-game.png`를 그대로 사용한다. 전체 조감도 대신 왕좌, 양옆 수호상, 창과 기둥이 보이는 구도이며 로비 카드와 맵 선택창이 같은 이미지를 읽는다. 재촬영 시 해당 PNG를 대표 이미지 경로에 복사한다. 교체 전 이미지·로비 확인 캡처·배포 파일 검증 기록은 `artifacts/castle-preview-update/`에 보관한다.

## 스폰 규칙

자신의 팀과 현재 A/B 단계에 해당하는 **활성 아군 스폰**에서만 보호된다. 중심 기준 X ±6.5m, Z ±3m, 발 높이 Y 0~2.25m이다. 기존 캐릭터 변경 판정과 같은 부피를 사용한다. 바닥의 밝은 테두리와 HUD가 상태를 알려준다.

- 체류 시간이 지나거나 직접 공격하더라도 구역 안에서는 피해를 받지 않는다.
- 일반 공격·스킬·궁극기·폭발·기존 지속 피해의 HP/보호막 손실과 공격자의 피해 기반 궁극기 충전을 차단한다.
- 적 대상 탐색, 새 도발/지속 효과, 밀쳐내기를 차단한다. 진입 이전 상태 효과는 남은 시간이 경과하며, 기존 지속 피해는 구역 밖으로 나가면 남은 시간 동안 다시 적용된다.
- AI는 보호 대상을 조준·사격·공격 스킬 대상에서 제외한다. 직전 근접 추격 대상이 스폰으로 들어가면 저장된 경로를 즉시 버리고 다른 적이나 거점으로 향한다. 도발도 이 제외 규칙을 무시하지 못한다.
- 나가면 구역 보호가 즉시 해제되고, 재진입하면 다시 적용된다. 적 스폰과 비활성 스폰은 보호하지 않는다. 기존 부활 직후의 2초 보호는 별도 규칙으로 유지한다.
- 같은 서버 판정을 솔로/호스트/전용 서버가 사용한다. 현재 프로젝트의 맵 선택 동기화 프로토콜은 `TSBD`이며 이전 맵 지형의 빌드와 혼용하지 않는다.

## 검증

스폰 위치·경계·팀·A/B 전환, 전 피해 분류와 보호막 보존, 지속 피해 진입/이탈, 도발 대상 제외, 추격 즉시 해제/재획득을 검사한다. 현재 구조 검사는 두 진행축의 각도, A–B 시야 차단, 기본 7개 동선과 공간 방문 6개 동선의 모든 선분, 각 단계·팀 스폰에서 거점까지 실제 이동, A 고지대 계단 2개와 창문 통행, B 홀의 지상 통행과 다리 충돌 제거를 확인한다. 카페 테라스·서재·나무 광장·중정·수호상 홀·왕좌 단상의 경로도 같은 실제 이동 판정으로 확인한다.

v3 전체 타깃 테스트 144개가 통과했고 기존 오디오 장치 검사 1개는 ignored다. fmt, 경고를 오류로 취급한 Clippy, 클라이언트/서버 빌드를 확인했다. 최종 5,811개 메시·318,433개 삼각형을 545개 공간/재질 청크로 내보냈으며, 충돌 블록은 340개다. `build-report.json`에 수치를 기록한다. 퇴화 면이 없는지 확인한 뒤 내보내며, 얇은 왕좌·창·의자 패널에는 두께를 넣어 FBX의 뒷면 컬링 문제를 방지했다.

검증 로그와 최종 파일 해시는 `artifacts/castle-concept-v3/`에 보관한다. 변경 전 v2 모델·구조·관련 소스는 같은 폴더의 `before/`에 있다. 자동 테스트와 별도로 제공된 그림·Blender 렌더·실제 게임 캡처를 대조한다. 다인 실전 밸런스와 원화 수준의 재질·광선 표현은 이 검증의 범위 밖이다.

## 2026-11-14 외성문 아치 수정

`052 Outer gate wall lintel`은 아치 장식 뒤에 직육면체 벽이 남아 입구를 가리고 있었다. 해당 벽체를 폭 8m, 시작 높이 3m, 중앙 높이 5m의 타원형 아치 개구부로 수정했다. 벽 두께 0.4m와 상단 높이 6.2m를 유지하며, 앞·뒤·아치 안쪽 면이 연결된 편집 가능한 메시다. `Gate moulding`을 같은 곡선에 맞추고 입구 바닥을 가로지르던 장식 띠를 제거했다.

`castle_gate_arch.py`가 시각 메시와 충돌에 쓰는 곡선을 공유한다. 기존 052번 충돌 블록은 상단 덮개를 맡고, 64개 비표시 충돌 블록이 양쪽 곡선을 근사한다. 보수적 충돌 오차는 최대 0.1m 미만이며, 기존 블록 번호와 지상 통행 폭은 유지한다. `castle_layout.py`와 `build_castle.py`로 다시 생성해도 수정이 유지된다.

저장된 Blender 원본의 수동 편집을 보존하기 위해 `repair_castle_gate.py`로 해당 부분만 교체했다. 다른 5,833개 객체의 메시·UV·재질 연결·배치·컬렉션이 그대로인지 비교했으며, 수정 직전 원본과 전후 렌더는 `artifacts/castle-gate-arch/`에 보관한다. 원본과 게임용 FBX를 함께 갱신했다. 아치 수정 직후에는 5,810개 메시, 319,469개 삼각형, 545개 FBX 청크, 404개 충돌 블록이었다. 이 수치와 기존 v3 검증 기록은 당시 결과로 유지한다.

`verify_castle_gate_arch.py`에서 저장된 Blend의 닫힌 메시·면적·체적·개구부 광선 검사, 앞뒤 렌더와 FBX 재가져오기 검사를 통과했다. `cargo test --locked --no-default-features --test castle --test multilevel`의 12개 테스트, `cargo fmt -- --check`, `cargo build --locked --bins`도 통과했다. 이번 수정의 검증 로그와 에셋 해시는 `artifacts/castle-gate-arch/verification.json` 및 같은 폴더의 로그에 있다.

## 2026-11-14 B 다리 제거

요청에 따라 B 홀의 다리 본체, 14단 계단, 남북 착지대, 난간과 받침기둥을 모델·충돌·고지대 동선에서 제거했다. 양쪽 다리 전용 상부 출입구는 벽으로 마감했다. B 거점, 왕좌 단상, 기존 남북 지상 출입구와 A의 고지대 계단은 유지한다. 맵 리뷰의 다리 시점은 B 홀 지상 시점으로 바꾸고 평면도도 갱신했다.

`remove_castle_bridge.py`가 현재 Blend의 다리 관련 객체 63개만 제거하고 두 출입구를 마감한다. 외성문 아치를 포함한 다른 객체 5,772개의 메시·UV·재질 연결·배치·컬렉션을 보존했으며, 구조 객체의 충돌 번호는 갱신된 레이아웃에 맞춰 재연결한다. `castle_layout.py`에도 제거를 반영하여 재생성 시 다리가 돌아오지 않는다. 변경 전 원본·FBX·레이아웃과 검증 결과는 `artifacts/castle-bridge-removal/`에 보관한다.

제거 후 모델은 메시 5,753개, 삼각형 316,257개, FBX 청크 542개이며 충돌 블록 379개와 동선 13개를 사용한다. `castle`·`multilevel` 테스트 12개에서 다리 없는 B 홀 통행, 옛 계단·다리·착지대 위치의 지면 낙하, 남은 A 고지대와 외성문 아치를 확인했다. `verify_castle_bridge_removal.py`는 저장된 Blend와 FBX에서 다리 잔여물이 없는지 광선으로 검사하고 전후 렌더를 저장한다.
