# 커뮤니케이션 휠

2026-11-12 구현. 오버워치의 원형 커뮤니케이션 조작을 참고하되, 배치와 기능 범위는 사용자 요청을 따른다. 아이콘은 Fyrox 벡터 도형으로 직접 작성했다.

## 조사

- [블리자드 공식 핑 시스템 설명](https://overwatch.blizzard.com/en-gb/news/23785337/an-inside-look-at-the-ping-system-in-overwatch-2/): 커뮤니케이션 휠의 집결·치유 요청을 팀 협동에 사용하는 흐름을 확인했다. 원작의 머리 위 핑 기능까지 이번에 구현한 것은 아니다.
- [블리자드 2020년 5월 패치 노트](https://overwatch.blizzard.com/en-gb/news/patch-notes/live/2020/05/): 커뮤니케이션 휠 확장과 반복 사용 간격을 참고했다. 이 게임은 일반 항목 0.75초·음성 대사 4초 간격을 사용하며 원작의 충전식 제한을 재현하지 않는다.
- [블리자드 포럼의 휠 사용 중 입력 충돌 보고](https://us.forums.blizzard.com/en/overwatch/t/communication-wheel-allows-ability-use-before-swapping-page/1000337), [휠 종료 시 카메라 이동 보고](https://us.forums.blizzard.com/en/overwatch/t/commemote-wheel-flicks-camera-after-selecting-option-pc/1043403): 사용자 보고를 회귀 점검 항목으로 삼았다. 공식 동작 명세로 취급하지 않는다. 구현에서는 휠 동안 전투 입력을 차단하고 마우스를 워프시키지 않는 상대 이동 포인터를 쓴다.

## 조작과 배치

C를 누르면 즉시 열린다. 마우스를 원하는 방향으로 움직이고 C를 놓으면 한 번 실행한다. 마우스 버튼을 누를 필요는 없다. 중앙 반경 58픽셀은 취소 영역이다. 우클릭·Esc·창 포커스 이탈도 취소한다. 채팅 작성·캐릭터 선택 중에는 휠을 열지 않는다.

| 방향 | 항목 | 실행 |
|---|---|---|
| 위 | 감정 표현 | 기존 춤 시작 + 팀 채팅 |
| 오른쪽 위 | 안녕 | 인사 채팅 + 1인칭 시점 유지 + 생존·행동 가능 시 1.8초 손 흔들기 |
| 오른쪽 | 치유 요청 | ‘치유가 필요합니다!’ |
| 오른쪽 아래 | 집결 | ‘제게 집결해 주세요!’ |
| 아래 | 궁극기 상태 | 실제 서버 충전율 또는 100% 준비 완료 |
| 왼쪽 아래 | 음성 대사 | 원본 한국어 친밀도 대사 재생. 서버 승인 후 주변 팀원에게도 재생(4초 간격) |
| 왼쪽 | 응답 | ‘알겠습니다!’ |
| 왼쪽 위 | 감사 | ‘감사합니다!’ |

실행 문구는 아군에게만 파란 팀 채팅으로 전달된다. 기존 자유 채팅의 선택 채널에는 영향을 주지 않는다. 상대는 인사 모션을 볼 수 있지만 팀 채팅은 수신하지 않는다. 사망 중에도 인사·치유 요청 같은 메시지는 보낼 수 있으며 모션은 재생하지 않는다. 감정 표현은 사망·전투 행동 제한 중 실행하지 않는다.

## 구현

- `src/communication.rs`: 8방향 판정, 취소 영역, 한 번만 실행되는 release, 서버 액션·쿨다운·문구, 인사 모션 곡선.
- `src/presentation/communication.rs`: 벡터 원형 UI·아이콘, 선택 강조, 사망 중 대사 사용 불가 표시.
- `src/presentation/first_person.rs`: 선택한 캐릭터 FBX의 `UpperArm.R`·`Forearm.R`·`Hand.R`에 연결된 원본 메시로 1인칭 오른팔을 만든다. 원본 정점·스키닝·UV·재질·텍스처를 보존하고 표시할 삼각형만 분리한다. 캐릭터 변경 시 함께 교체한다.
- `src/presentation/characters.rs`: 기존 FBX 애니메이션 평가 뒤 오른팔·팔꿈치를 보간하는 상체 모션. 캐릭터 원본 에셋은 이 기능을 위해 다시 생성하지 않는다.
- `src/net.rs`: 인증된 발신자의 액션 요청·확인·재전송과 서버의 팀 채팅 라우팅. 인사 잔여 틱을 모든 플레이어의 스냅샷에 포함한다. 재전송은 채팅이나 인사를 다시 시작하지 않는다.
- 프로토콜은 TSB5. 호스트와 참가자 모두 새 실행 파일을 사용해야 한다. 최장 기존 스냅샷도 1,200바이트 미만이다.

공격·스킬·궁극기·재장전·피격·사망·캐릭터 교체는 손 흔들기를 해제한다. 인사 중 이동은 가능하다. 다른 플레이어의 인사는 동일한 서버 잔여 틱에서 계산된다.

안녕은 3인칭 카메라로 전환하지 않는다. 본인은 1인칭 화면에서 무기를 잠시 내리고 실제 캐릭터의 오른손을 흔든다. 손등이 카메라를 향하고 엄지가 화면 안쪽에 오는 방향이며, 소매와 위팔은 화면 아래로 이어진다. 전용 임시 손 도형은 사용하지 않는다. 1인칭 팔은 현재 무기를 잡은 자세를 기준으로 어깨·팔꿈치 위치와 크기를 유지한다. 원본 리그의 손·전완·소매를 팔꿈치 주위로 함께 회전하고 손가락을 펼치며, 시작 0.25초와 마지막 0.3초 동안 파지 자세와 보간해 인사와 무기 복귀를 연결한다. 인사 중에도 무기의 이동 흔들림을 공유한다. 다른 플레이어에게는 상체 인사 모션이 보인다. 관절의 FBX 기준 회전은 두 시점 모두 반영한다. 춤 상태와 인사 상태가 겹쳐도 인사 중에는 1인칭 카메라가 우선한다.

## 검증

헤드리스 전체 테스트 80개, Clippy 경고 금지, 실행 파일 빌드로 검사한다. 추가된 5개 테스트는 8방향·취소·단발 실행, 실제 궁극기 수치, 모션 만료/취소, UDP 팀 공개 범위·관전자/늦은 참가 동기화, ACK 유실·재전송·위조·잘못된 패킷을 다룬다.

`cargo run --bin tsb -- --communication-review`는 입력 및 월드 상태를 고정한 검증용 실행이다. 8개 휠 선택 상태·기본 1인칭 인사·15명 각각의 1인칭 인사, 총 24장을 `artifacts/preview-communication-*.png`에 저장하고 종료한다. 인사 캡처마다 1인칭 카메라 위치·손 표시·자기 몸 숨김·손 메시의 캐릭터 일치를 검사한다. `FIRST_PERSON_ARM_OK`는 각 캐릭터의 원본에서 분리한 삼각형 수와 사용 재질 수를 기록한다. 검증 모드에서도 인사를 3인칭으로 전환하지 않는다. 정상 플레이에서는 실제 C 입력과 서버 액션을 사용한다.

`--greeting-review`는 15명 각각 무기 파지·손 올리기·좌우 흔들기·내리기·무기 복귀 6단계를 고정해 확인하고, Tripo 네 캐릭터의 다른 플레이어에게 보이는 인사도 캡처한다(총 94장). 카메라 고정, 본인 전신 숨김, 무기/손 전환, 복귀 후 손잡이 접촉 오차를 검사한다. 각 캐릭터의 실제 리그에서 시작·종료를 포함한 109개 틱도 순서대로 검사해 팔꿈치·어깨 고정, 팔 길이 유지, 손목 위치·손 회전의 연속성, 시작·종료 시 파지 일치를 확인한다. 소매 정정 전후 자료는 `artifacts/greeting-sleeves/`, 인사 연결 검증은 `artifacts/greeting-continuity/`에 보관한다.
