# 참가자 이동 동기화 수정

2026-11-13. EOS P2P / 직접 UDP 연결 방식과 60Hz 서버 시뮬레이션,
20Hz 상태 전송 주기는 유지한다.

## 변경 내용

- 참가자는 입력을 보낸 프레임에 자신의 이동·점프·유령 영체화를 먼저 계산한다.
  서버와 `movement::step_actor`를 공유해 벽·계단·바닥·천장·유령 벽 통과 규칙을 맞춘다.
- 서버 스냅샷은 해당 참가자의 처리된 입력 번호, 수직 속도, 이동 관련 상태 시간을 포함한다.
  참가자는 확인된 입력을 버리고 나머지만 서버 위치에서 다시 적용한다.
  작은 위치 오차만 화면에서 서서히 줄인다. 영체화 발동·만료·벽 배출은 서버와 동일하게 예측하고, 피해·탄약·거점·부활은 서버가 판정한다.
- 다른 플레이어의 위치와 시선은 서버 틱 기준 약 100ms 버퍼에서 보간한다.
  사망·부활·캐릭터 변경·라운드/맵 변경·큰 위치 변경에는 이전 보간/예측을 이어 붙이지 않는다.
- 미확인 입력은 최대 30개, 스냅샷 이력은 최대 16개다. 0.5초 이상 상태가 오지 않으면
  예측 이동을 멈추고 연결이 회복될 때 이전 입력을 초기화한다.
- 돌진 등 스킬 이동과 외부 넉백은 서버 상태로 보정한다. 사격 판정의 과거 시점 보상은
  이 수정 범위에 포함되지 않는다.

## 버전과 표시

프로토콜은 `TSBG`다. `TSBF`는 기존 EOS 분할 프레임 표식이므로 사용하지 않았다.
기존 `TSBE` 빌드와 호환되지 않으므로 방장과 참가자가 모두 새 EXE를 사용해야 한다.
최대 게임 데이터그램은 1200바이트 미만을 유지하며, 이동 정보 공간 확보를 위해
스냅샷의 짧은 경기 안내 문자열을 UTF-8 경계에 맞춰 최대 56바이트로 제한한다.
별도 채팅 패킷의 길이는 바뀌지 않는다.

우측 상단 `RTT`는 입력 송신부터 그 입력을 확인한 스냅샷 수신까지의 시간이며
서버 갱신 대기를 포함한다. `FPS`는 렌더러가 측정한 실제 화면 갱신 횟수다.
5초마다 `PERF:` 로그에 FPS, 렌더링 시간, 플러그인 갱신 시간, 마지막 스냅샷 수신 후
경과 시간을 기록한다. 과거 표시의 ms는 왕복 지연이 아닌 스냅샷 수신 후 경과 시간이었다.

## 검증

- 입력 즉시 반영, 확인된 입력의 중복 재적용 방지, 점프 수직 속도/착지,
  일반 벽 충돌과 유령 통과, 둔화·기절, 사망·부활·캐릭터·맵·라운드 전환.
- 100ms 왕복 지연에 추가 0–33ms 지연 변동과 스냅샷 손실을 넣은 결정적 시뮬레이션.
- 20Hz 원격 상태 사이의 연속 이동, 시선 각도 경계 보간, 장기 수신 중단/복구.
- 실제 로컬 UDP에서 서버 응답 없이 6프레임 이동한 뒤 서버와 위치 수렴 확인.
- 12명 스냅샷의 MTU, 입력 확인/이동 상태 왕복, 잘못된 필드와 이전 프로토콜 거부.

검사 로그와 수정 전 원본은 `artifacts/client-motion-fix/`에 보관한다.
로컬 UDP 및 지연 모의 검증은 실제 두 PC의 EOS Direct/Relay 회선 품질 검증을 대신하지 않는다.
